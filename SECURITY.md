# 🛡️ Security Policy

## Responsible Disclosure

We take the security of our simulations and firmware seriously. If you discover a security vulnerability that could compromise the administration console (e.g., unauthenticated log exposure to external clients) or crash the microcontroller unexpectedly, we encourage you to notify us.

Please do not report vulnerabilities through public GitHub issues. Instead, communicate privately with the maintainer so we can address the concern.

---

## Reporting a Vulnerability

To report a vulnerability:
1. Draft an email to the maintainer or send a direct communication to the contact address in [README.md](README.md#maintainer--contact).
2. Include the following details in your report:
   - **Vulnerability Description:** What is the underlying issue?
   - **Proof of Concept (PoC):** Step-by-step instructions or scripts to reproduce the issue.
   - **Hardware/Firmware Info:** Version of the firmware, build configurations used, and physical connections.
   - **Impact:** What does this vulnerability expose?

---

## Disclosure Policy

We operate under a coordinated disclosure policy:
- Once a report is submitted, we will acknowledge receipt within 48 hours.
- We aim to fix critical security flaws within 30 days of receiving the report.
- We request that you do not publish the vulnerability details until a patch or mitigation instructions have been integrated into the repository.
